# Contributing

Maintainer: nahmedpsu. Propose changes through issues and pull requests; never include sensitive system details in either.

## Development expectations

Run the offline tests before submitting a change. Keep development fixtures explicitly labelled and distinguish proposed checks from implemented, independently evaluated capabilities.

New live-adapter work requires a documented threat model and owner-controlled execution design before any operational run. Do not assume a GitHub contribution or API account grants permission to test an institution's system.

## Evidence and claims

No fabricated evaluation results, approvals, affiliations, DOIs or performance claims are acceptable. Public reports must identify the exact software version, configuration scope and unresolved cases without exposing operational data.

Record meaningful development assistance accurately, including AI assistance when relevant. Do not alter contributor attribution or imply that a contributor endorses unverified findings.
