# Security and responsible use

This is a development scaffold, not a certified security product. It currently contains no live-network execution path.

## Reporting issues

Do not open a public issue containing credentials, personal data, exploit details for a live registry or restricted logs. Use GitHub private vulnerability reporting if enabled; otherwise open a minimal issue requesting a private contact channel without including sensitive details.

Institutional system findings must follow the system owner's approved disclosure process, not automatically this repository's issue tracker. Do not contact or test third-party services without separate scope approval.

## Credential handling

Never paste credentials into chat, repository files, issues or commit messages. If a credential is exposed, rotate or revoke it through the issuing service; removing a file or message alone does not revoke access.

Git ignore rules and structural schema checks cannot guarantee that files contain no personal data. Review staged files and commit history before any publication.
